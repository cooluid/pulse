# 一日一印（Pulse）产品路线图

文档版本：1.0  
状态：Canonical Execution Plan  
更新时间：2026-08-12

本文只定义版本顺序、进入条件与商业边界。当前正式范围以 [RELEASE_SCOPE_1_1.md](./RELEASE_SCOPE_1_1.md) 为准，事实语义以 [DOMAIN_CONTRACT.md](./DOMAIN_CONTRACT.md) 为准。

## 1. 决策原则

1. 版本号不是停止开发的理由；未上线也不是无限扩张的理由。每一项能力必须解决明确用户问题，并关闭它新增的数据、隐私、恢复、无障碍与系统生命周期风险。
2. 不设置“必须 30 人才能开发”的仪式性数字。进入实现依赖工程可证性与风险；决定留存、付费或长期价值，依赖真实使用证据。样本量由决策误差、风险和效应大小决定，并在实验开始前登记。
3. 不保留两套 schema、归档、Repository、媒体路径或权益判断。首个公开版前采用 clean break；首个公开版后才建立显式迁移与兼容测试。
4. 免费签到永远不被影像、网络、同步、订阅或系统扩展阻塞。用户自己的签到与原始照片始终可查看、删除并进入完整加密备份。
5. 不用“功能很多”代替差异化。Pulse 的产品主张是：每天落下一枚真实印记，时间让它成为私人档案。

## 3. 1.1：今日入镜正式基线

### 3.1 产品语义

- 只有签到事实保存成功后才邀请“今日入镜”；邀请可永久关闭，永不阻塞签到。
- 相机权限只在用户点击拍摄时请求；拒绝、取消、处理失败或空间不足不撤销签到。
- 每个逻辑日最多一张正式影像，可重拍。新文件完整安装并提交元数据后，旧文件才成为可回收孤儿。
- 照片与签到独立：删照片不删签到；删签到保留照片并解除关联；同日重新签到会重建关联。
- History 同时表达“有签到”“有影像”“两者都有”，不把照片伪装成签到证据。
- 原图与缩略图不进入 Widget、Live Activity、Lock Screen、StandBy、通知或共享偏好。

### 3.2 数据与恢复

- 唯一 schema 为 1.1.0，唯一归档为 `.pulsebackup` v2；不接受预发布 v1。
- SwiftData 保存元数据，受保护文件仓储保存不可变 JPEG；原图和缩略图各有 byteCount 与 SHA-256 身份。
- 导出包含签到与全部媒体；逐条目 AES-256-GCM 认证，恢复先在隔离目录完成解密和完整性验证，再经确认全量替换。
- 清除数据删除记录、媒体、staging 和归档工作区；启动清理崩溃遗留与孤儿文件。

### 3.3 发布门禁

- Unit/UI 自动化、Debug/Release build、Analyze 和 String Catalog 编译通过。
- 真实 iPhone 覆盖后置/前置相机、首次授权、拒绝后恢复、取消、重拍、低存储、中断、重启与跨日。
- 真实照片导出、篡改、错误口令、恢复确认、替换、清除、卸载边界全部验证。
- VoiceOver、最大动态字体、Reduce Motion、深浅色、简中/英文、iPhone/iPad 布局通过。
- Widget、通知、Live Activity 与 StoreKit 既有能力没有回归。

“完成 30 位用户”不是以上工程门禁的替代物。未完成真机与 TestFlight 验收时不能宣称发布 GO，但可以继续开发并关闭确定性风险。

## 4. 1.2：更有辨识度的私人仪式

### 4.1 拍摄不是相机壳，而是“时间对齐仪式”

- 可选显示上一次用户主动选定照片的极淡轮廓，帮助保持构图；默认关闭，不保存人脸模板。
- 拍摄后只给构图、清晰度与光线提示，不做年龄、颜值、性别、健康或身份推断。
- 不合格照片仍可作为当天私人影像，只是明确“不进入流影候选”。
- 月历可以形成“印记 + 影像光窗”的双层时间纹理，颜色之外必须有形状/图标语义。

### 4.2 新鲜点

- **时间显影**：不即时奖励，每满 7/30/100 个真实日才逐渐显露一张抽象档案，不新增奖励数据库。
- **往日重影**：今天拍摄时只展示用户选择的某个往年同日轮廓，而不是算法评价。
- **缺席也诚实**：没有照片的日期保留留白；未来影片不生成伪照片填洞。
- **一日一帧电影语法**：UI 以印记、光窗、暗房显影为统一品牌隐喻，照片仍是内容层，不建立第二套相机品牌。

### 4.3 证据门禁

先用内部真实设备和小规模 TestFlight 验证理解、摩擦与连续拍摄行为。若结果波动大或准备做付费/留存结论，再按预登记假设扩大样本；不得事后用任意“30 人”包装结论。

## 5. 1.3：真实上下文

新增 `DayAnnotation` 前必须先更新 schema、归档和删除合同。回响和缺席说明不创建、不延续、不补写签到事实；今天结束前不能标为缺席。是否继续取决于真实使用、访谈理解与不降低核心签到率，而不是代码已写多少。

## 6. 2.0：Pulse Plus

Plus 首发不能只是主题包。至少同时具备持续价值中的三项：长期节律、个人印期、持续回顾、私密同步、高级档案。价格只来自 StoreKit；页面和运行入口都验证同一权益；退款、撤销、过期或离线不会删除内容。

已购买 `co.fanr.pulse.enhancement.lifetime` 的用户永久保留 scheduled Live Activity 和三种额外 Home Screen Widget 构图。Plus 不得重复销售同一能力。

## 7. 2.1：岁月流影

实现顺序固定：

1. 真实照片按日期排序与稳定裁切；
2. 用户主动选择进入影片的照片；
3. 本地关键点对齐和网格形变；
4. 相邻真实照片的纹理融合；
5. 按真实日期映射时间轴，缺失日留白；
6. 30/90/365 天和自选区间导出；
7. 1080p/4K 与年度档案。

默认本地处理，不静默上传人脸。生成帧只是视觉过渡，不写回每日事实。渲染缓存、取消、失败、进度、后台终止与清除语义必须在收费前闭环。

### 免费与收费边界

- 永久免费：拍摄、查看、删除、关闭邀请、原始照片与签到的完整加密备份/恢复。
- 可收费：智能对齐、长区间流影、年度影片、4K、跨阶段比较和高级档案排版。
- 权益结束：既有原图和已生成可导出成果继续可读；停止新的 Plus 渲染，不锁住或降质用户原始资料。

## 8. 明确 NO-GO

- 用签到照片做考勤证明、位置证明或防作弊。
- 自动补签、连续冻结、失败后伪成功或占位照片。
- 面龄、颜值、身份、健康或人格推断。
- 为生成效果静默上传人脸，或以低清占位替代丢失原图。
- 为收费锁住用户自己的照片、删除权或完整备份。
- 未定义冲突与退出语义就接入云同步。
- 将固定用户数当作所有产品与工程决策的通用门槛。
