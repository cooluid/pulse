# 一日一印（Pulse）日签到产品需求

文档版本：1.8<br>
状态：Canonical Product Contract
适用范围：本地优先、单用户、单一主承诺日签到产品

## 1. 背景与目标

用户需要一个低干扰的日签到工具，每天用极少操作记录“今天已经完成签到”，并能可靠查看连续天数和历史记录。

MVP 的目标不是搭建任务平台，而是让以下闭环稳定成立：

1. 用户知道今天是否已经签到。
2. 用户能在两秒内完成签到。
3. 应用重启、快速连点和日期切换不会产生错误记录。
4. 用户能从历史记录理解自己的坚持情况。
5. 用户能在首次确认与设置中明确管理唯一主承诺，而每日主流程不重复展示身份正文。

## 2. 用户与使用场景

### 2.1 目标用户

- 使用自己的 iPhone 或 iPad 进行个人日签到。
- 不需要团队、审批或考勤证明。
- 希望记录长期保留，但首版接受本地数据边界。

### 2.2 核心场景

- 每天打开 App，确认状态并签到。
- 首次使用时确认唯一主承诺，并可选择记录一句“为什么重要”。
- 在承诺变化时修改名称或说明，不影响既有签到事实。
- 收到提醒后打开 App 签到。
- 查看本月哪些日期已签到或漏签。
- 查看当前连续天数、最长连续天数和累计签到数。
- 删除误操作产生的签到记录。

## 3. 产品原则

- **单一主操作**：今日页的视觉中心是签到按钮。
- **事实优先**：只有保存成功的记录才算签到成功。
- **离线完整**：核心功能不依赖网络。
- **状态明确**：不能只靠颜色表达已签到、漏签或未来日期。
- **允许纠错**：这是个人记录工具，不以人为制造的不可撤销限制冒充数据可信度。
- **克制扩展**：积分、社交和勋章不得先于记录可靠性。

## 4. 信息架构

产品使用首次确认页、两个主页面；设置从今日页工具栏进入。

### 4.1 主承诺确认

- 首次创建或完整清除数据后，先确认唯一主承诺，再进入主界面。
- 默认名称可以一键继续，不要求选择模板；用户也可以直接填写自己的名称。
- “为什么重要”为可选单句说明，不参与签到、统计或提醒判断。
- 首次确认不请求通知、评分、网络或其他系统权限。
- 未成功保存前不得进入主界面；保存失败保留输入并显示诚实错误。
- 从旧版本迁移或导入尚未确认的身份时，使用已有名称预填并要求确认，不重建项目或记录。

### 4.2 今日页

页面包含：

- 当前逻辑日期和星期。
- 周轨迹后的连续状态：只显示“从今天开始”或当前连续天数，不使用卡片、胶囊、栏目标签或通用鼓励语。
- 今日签到主按钮。
- 今日状态和签到时间。
- 当前连续签到天数。
- 最近 7 个逻辑日的签到概览。
- 进入设置的按钮。

今日页身份与节奏要求：

- 主承诺名称与“为什么重要”继续由同一 `Habit` 持久化，并在首次确认与设置编辑页完整呈现；二者都不进入今日页根界面。
- 连续天数为零时显示“从今天开始”，不得以“0 天”制造失败计分感；大于零时显示完整的“连续 N 天”。
- 连续状态在周轨迹下方沿同一中轴居中，所有字号与 iPhone / iPad 布局使用同一信息拓扑；不得使用左右分栏或让承诺长度改变今日页结构。
- 连续状态没有边框、阴影、材质背景或点击语义，不得与底部主导航形成第二个导航层。

今日状态：

| 状态 | 主按钮 | 页面反馈 |
| --- | --- | --- |
| 未签到 | 可点击，标题“今日待签到” | 不显示圆外重复状态文案 |
| 保存中 | 禁止再次触发 | 显示进度，不播放成功反馈 |
| 已签到 | 显示完成状态 | 显示签到时间和轻量成功反馈 |
| 保存失败 | 恢复可点击 | 提示“签到未保存，请重试” |
| 新的一天 | 恢复未签到 | 日期、最近 7 天和统计同步刷新 |

交互要求：

- 签到成功后使用轻量触觉和短动画。
- 今日页成为当前页时，待签到印记最多进行一次不超过两秒的有限呼吸；不得使用无限循环动画持续争夺注意力。
- 保存成功后按“空心印记 → 收缩为一点 → 实心印记”完成一次落印；已有记录在启动或回前台时只显示静态完成态，不重播仪式。
- Reduce Motion 只使用短淡入和静态形状替换；保存失败恢复待签到状态，不出现成功触觉、实心印记或完成时间。
- 动画不能阻止用户离开页面，也不能晚于持久化状态反映结果。
- 用户快速连续点击时，界面和数据层都必须防止重复写入。
- 应用从后台返回或停留前台跨日时，自动重新计算今日状态。

### 4.3 记录页

页面包含：

- 月份切换。
- 月历网格。
- 累计签到、当前连续和最长连续统计。
- 日期详情。

月历状态：

- 已签到：实心标记和勾选图标。
- 漏签：弱化标记和明确的未完成语义。
- 今天：独立边框，不与签到状态冲突。
- 未来日期：不可操作且不计为漏签。
- 项目创建前的日期：不计为漏签。

用户点击已签到日期后，可查看实际签到时间并删除该记录。删除必须二次确认；删除成功后所有统计立即重新计算。

记录详情使用可下拉关闭的系统 Sheet，不额外显示“完成”按钮；删除确认必须从“删除签到记录”按钮自身呈现。

首版不允许点击空白历史日期创建签到，即不支持补签。

### 4.4 设置页

`P0`：

- 主承诺名称和“为什么重要”的正式编辑入口。
- 触觉反馈开关。
- 当前签到时区展示。
- 清除全部数据。
- App 版本信息。

`P1`：

- 每日提醒开关。
- 提醒时间。
- 一周起始日。
- 主题模式设置：跟随系统、浅色、深色。
- 应用内语言设置：跟随系统、English、简体中文；切换后立即生效。
- 数据导出。
- 从 Pulse JSON 导出文件恢复数据；导入采用全量替换，不做隐式合并。
- 修改签到时区。

分组说明必须进入对应卡片：单项规则作为控件副说明，整组规则作为卡片内说明行。破坏性确认必须绑定实际触发行，不得挂在整页容器上。

通知权限只在用户主动开启提醒时请求。首次启动不得直接弹出通知权限。

提醒采用滚动 60 个日历日的一次性本地通知：今天已过提醒时间时从明天开始，已签到日期不生成请求；启动、回到前台、签到或提醒相关设置变化时刷新。若用户超过 60 天没有重新打开 App，窗口之外的提醒不保证送达，产品支持页必须如实说明这一边界。

## 5. 功能范围

### 5.1 P0：核心 MVP

- 首次启动创建默认主承诺并要求用户确认；默认名称可一键继续。
- 单一主承诺命名、可选“为什么重要”和后续编辑；修改不改写历史签到事实。
- 今日签到和持久化。
- App 内有限日印仪式；只在签到事实提交成功后落下实心印记。
- 当日唯一性与快速连点保护。
- 今日状态恢复和跨日刷新。
- 最近 7 天概览。
- 月历历史。
- 当前连续、最长连续和累计签到统计。
- 删除单条错误记录。
- 清除全部数据。
- 深色模式、动态字体和 VoiceOver 基础支持。
- iPhone 与 iPad 自适应布局。
- 单元测试和核心 UI 测试。

### 5.2 P1：1.0 增强范围

- 每日本地提醒。
- 版本化 Pulse JSON 数据导出与全量恢复。
- 签到时区设置。
- 一周起始日设置。
- 更完整的错误恢复和空状态说明。
- App 图标、启动体验和正式发布素材。

### 5.3 P2：后续候选，不属于 MVP 承诺

- 隐私锁和可交互的桌面/锁屏小组件；Widget 只能消费共享正式 store，默认不在锁屏或系统表面泄露主承诺，未完成 App Group 迁移时不可写，详细范围以 [WIDGET_SHARED_STORE_CONTRACT.md](./WIDGET_SHARED_STORE_CONTRACT.md) 为准；
- 跨系统“呼吸、落印、年轮”仪式：签到成功后的短暂灵动岛回声、回归和事实里程碑，以及经用户开启和远程门禁验证后的留印提醒窗口；App 内基础落印已属于 P0，不在此重复；
- 与签到事实分离的轻量回响和缺席说明，不形成补签；
- Apple Watch 伴侣 App、表盘 complication、Smart Stack、可靠离线命令与高级节律，Shortcuts 和其他高级系统入口；
- 通过冲突原型门禁后的私密多设备同步；
- 签到成功后可选的“今日影像”，以及与 `CheckInRecord` 分离的媒体存储、删除、导出和恢复；
- 将合格单人面貌照片本地对齐、网格形变和渐变融合的“岁月流影”，不做年龄、颜值或身份推断；
- 节律、印期、持续回响、长期档案等 Pulse Plus 能力；
- 微信提醒仅作为官方资格轨候选：主体、类目、模板、用户授权和真实发送全部通过后，才评估为本地提醒之外的可选通道。

后续候选的 GO / HOLD / NO-GO、免费与收费边界、数据合同和阶段门禁以 [PRODUCT_STRATEGY_2_X.md](./PRODUCT_STRATEGY_2_X.md) 与 [POST_1_0_ROADMAP.md](./POST_1_0_ROADMAP.md) 为准；Widget、Live Activity、灵动岛、Apple Watch 和提醒通道语义以 [PULSE_RITUAL_CONTRACT.md](./PULSE_RITUAL_CONTRACT.md) 为准。多个并行项目继续 `HOLD`；补签、连续冻结、AI 面龄、全天常驻未签到灵动岛和非官方微信个人号自动化为 `NO-GO`。

### 5.4 明确不在 MVP 范围

- 登录注册。
- 社交、排行榜或好友监督。
- 积分商城和付费体系。
- 服务器防作弊。
- 团队考勤、审批或证明。
- 自动补签。
- 未定义冲突策略的多设备同步。

## 6. 业务规则引用

逻辑日、唯一性、连续天数、统计、删除和跨时区规则只以 [DOMAIN_CONTRACT.md](./DOMAIN_CONTRACT.md) 为准。

## 7. 非功能需求

### 7.1 性能

- 冷启动后首页应在本地数据加载完成时立即可交互。
- 用户点击签到到 UI 确认的目标时间小于 300 毫秒，不包含系统极端负载。
- 10 年每日一条记录的规模下，月历和统计仍应流畅。
- 统计计算不得阻塞主线程产生明显卡顿。

### 7.2 可靠性

- 数据保存失败不得显示成功。
- App 重启后状态与重启前一致。
- 同一个项目同一天最多存在一条有效记录。
- 主承诺身份修改不得改变项目 ID、起始日、时区或既有签到记录。
- 主承诺名称必须是规范化的 1...80 个字符；可选说明最多 160 个字符，具体规则以领域合同为准。
- 删除或清空数据应是显式操作，并在完成后刷新所有派生状态。

### 7.3 隐私

- P0 不发送签到数据到网络。
- P0 不集成第三方分析或广告 SDK。
- 除用户主动开启的通知权限外，不请求无关权限。
- App 内与商店资料使用同一公开隐私政策，设置页同时提供可达的产品支持入口。
- 若未来加入云同步或分析，必须更新隐私说明并与本地数据策略区分。

### 7.4 无障碍与适配

- 支持深色模式。
- 主题与应用内语言选择在重启后保持；清除全部数据后恢复为跟随系统。
- 主操作最小点击区域为 44 × 44 pt。
- 支持默认至 Accessibility 最大动态字体尺寸；超大字体下允许纵向滚动。
- VoiceOver 能读出日期、签到状态、连续天数和按钮行为。
- 状态区分同时使用文本、图标或形状，不能只用颜色。

## 8. MVP 验收摘要

满足以下条件才可判定产品 MVP 完成：

- 核心规则的自动化测试全部通过。
- 真机上完成首次启动、签到、退出重进、跨日模拟、删除和清空流程。
- iPhone 与 iPad 均无阻断性布局问题。
- VoiceOver 和深色模式完成手工检查。
- 已知数据丢失边界明确告知：P0 未启用云同步时，卸载 App 会丢失本地数据。
- 详细矩阵见 [TEST_PLAN.md](./TEST_PLAN.md)。

## 9. 发布前产品决策门槛

以下任一项未决定，不能把工程完成等同于公开发布准备完成：

- iOS / iPadOS 17.0 的最低版本行为是否已在可用的最旧 17.x 运行时和真实设备覆盖范围中验证。
- 本地数据在卸载后丢失是否符合产品承诺。
- 本地优先与 JSON 恢复承诺是否仍成立；任何 iCloud 或远程处理变更都必须先更新隐私政策。
- 正式视觉、图标、商店素材和文案是否验收。
- 通知行为是否在真机上通过授权、拒绝和系统设置变更验证。
