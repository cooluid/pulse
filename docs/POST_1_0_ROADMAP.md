# 一日一印（Pulse）1.0 之后开发路线图

文档版本：0.1  
状态：Proposed Execution Plan，不改变 1.0 已冻结范围  
评审日期：2026-08-11

本计划落实 [PRODUCT_STRATEGY_2_X.md](./PRODUCT_STRATEGY_2_X.md)。原则是一次只验证一个最大风险：先发布可靠性，再验证留存，再建立可收费价值，最后扩大平台与智能能力。

## 1. 总体顺序

| 阶段 | 目标 | 商业状态 | 进入下一阶段的必要证据 |
| --- | --- | --- | --- |
| R0：1.0 发布闭环 | 把当前免费核心真实交付 | 免费 | 1.0 全部发布门禁关闭 |
| R1：1.1 个性与留存 | 让用户明确“我为什么每天留印”并降低打开成本 | 免费 | 留存与目标用户反馈达到内部门槛 |
| R2：1.2 真实上下文 | 验证缺席说明、回归力和轻量回响是否有价值 | TestFlight 免费实验 | 使用率和访谈证明高阶价值 |
| R3：2.0 Pulse Plus | 上线节律、印期、持续回响与私密同步 | 年付 + 永久版 | 购买、续用、同步可靠性与退款达标 |
| R4：2.1 随身入口 | Watch、高级 Widget / Control、Shortcuts | Plus | 跨设备使用率证明维护价值 |
| R5：3.0 个性智能 | 用户自选观察维度和本地模式解释 | Plus 实验 | 解释正确、可关闭、隐私边界通过 |

任何阶段都不得绕过前一阶段的证据门禁。路线图不是发布日期承诺。

## 2. R0：关闭 1.0 发布门禁

### 2.1 范围

本阶段不加入 Widget、StoreKit、CloudKit、备注、补签或多项目。

按当前发布合同完成：

1. 正式 Bundle ID 的真实 iPhone 全新安装、签到、重启、删除、清除和触觉验证；
2. 真机通知授权、拒绝、系统外撤权、改时、签到后取消和重启行为；
3. 真实 iPad 横竖屏、分屏和持久化；
4. VoiceOver、最大字号、三种主题、双语、高对比度、降低透明度和 Reduce Motion；
5. 当前源码与 AppIcon Default / Dark / Tinted 最终视觉验收；
6. 签名 Archive、TestFlight 安装、升级与 JSON 恢复；
7. 复核已公开隐私政策与支持页在真实网络和设备上可达，并完成 App Store Connect 链接、商店文案和截图；
8. 跨多个自然日内部使用。

### 2.2 仓库边界决策

发布合同已经记录公开隐私政策与产品支持 URL，但当前 `site/` 源码仍是独立、未提交的嵌套 Git 工作区。发布前必须明确二选一：

- 作为独立站点仓库管理、构建、部署，并在主项目只记录正式 URL；或
- 清除其嵌套仓库边界后，作为主仓受控目录纳入版本管理。

在用户明确决定前，不移动、不合并、不删除该目录。还需用真实设备确认公开 URL 可达、部署内容与受控源码一致、联系邮箱可用，并在 App Store Connect 使用同一 URL；自动化访问被边缘防护拦截不能单独证明普通用户不可访问，也不能替代真机验证。

### 2.3 退出标准

- `RELEASE_SCOPE_1_0.md` 第 6 节全部通过；
- `IMPLEMENTATION_STATUS.md` 的发布结论改为 GO 有对应证据，不只改文字；
- 没有 P0/P1 数据、通知、无障碍或签名问题；
- 已建立真实版本的升级基线 fixture，后续 schema 变化不再 clean-break。

## 3. R1：1.1 个性与留存基础

### 3.1 产品范围

#### A. 主承诺身份，免费

- 首次启动先让用户确认主承诺名称，不强迫选择模板；默认值仍可一键继续。
- 可选填写一句“为什么重要”，不参与统计，不上传。
- 设置中提供正式重命名入口，变更不改写历史签到事实。
- 今日页用主承诺名称强化“这一枚是为了什么”，不能让标题挤压主操作和辅助功能。

#### B. 基础 Widget，免费

- Home Screen：显示今天状态、主承诺和连续节律；
- Lock Screen：只显示状态与入口，默认不泄露主承诺文本；
- 交互签到必须与 App 内签到走同一业务实现；若共享存储迁移未完成，只允许打开 App，不写第二份状态。

#### C. 隐私与反馈

- App 切回前台的可选 Face ID / Touch ID 锁；隐私锁免费；
- TestFlight 提供“分享测试快照”，用户预览后主动发送本地聚合，不附原始日期与文字；
- 在用户积累足够体验、且最近一次关键操作成功后才请求系统评分，不在首次启动请求。

### 3.2 技术准备

- 在领域合同中增加“重命名不影响事实”的规则，再增加 Repository 写入方法与测试；
- 为 Widget 建立 App Group store 迁移设计与中断恢复测试；
- 抽取 App / Widget 可共同编译的业务模块，禁止 Widget 直接写 SwiftData；
- 增加跨进程同日并发写入测试，唯一冲突必须回读现有记录并幂等成功；
- Widget 刷新失败只影响展示，不反向覆盖主 store。

### 3.3 验收

- 旧 1.0 store 升级后事实、时区、设置和 JSON 导出均一致；
- App 未运行、设备锁定、Widget 重载、快速双击和 App/Widget 同时签到不产生重复；
- 隐私锁不阻止通知协调和 Widget 的非敏感状态；
- D7 / D28 和 14 天快照达到战略文档初始门槛，或形成明确的修正结论。

## 4. R2：1.2 真实上下文与回归实验

本阶段先在 TestFlight 免费验证，不立即收费。

### 4.1 数据合同

新增 `DayAnnotation`，与 `CheckInRecord` 分离：

- `annotationKey = lowercased(habitID) + ":" + logicalDay`；
- 同一主承诺、同一逻辑日最多一个上下文对象；
- 支持短文本回响、是否值得记住、预定义缺席原因；
- 注释可存在于已签到日或已过去的缺席日；
- 注释永远不能创建、补写或延续签到事实；
- 未来日期不能写缺席原因；今天在日界线结束前不能标记为缺席；
- 删除签到与删除注释分开确认；JSON schema 新版本明确导出和恢复注释。

不在首个实验加入照片、自由标签系统或 AI。

### 4.2 产品实验

#### A. 三秒回响

签到成功后提供一个可跳过的轻量入口：一句话或一个“值得记住”标记。它不能阻塞两秒签到主流程，也不能每次弹出强制 Sheet。

#### B. 真实缺席说明

过去的缺席日可选择“休息、旅行、身体状态、忘记、其他”等少量原因并写一句说明。月历仍明确显示未签到，统计不因此增加。

#### C. 回归力原型

只从签到事实派生：

- 中断次数；
- 中断后 1/3/7 天内回归比例；
- 当前恢复阶段；
- 最近 28 天完成率。

措辞必须描述事实，不做心理、医疗或人格诊断。

### 4.3 继续门槛

- 至少 30 个用户完成 14 天实验；
- 至少 30% 的实验用户在 14 天内写入 5 次以上三秒回响，或至少 30% 的发生缺席用户使用缺席说明；
- 访谈能复述“回归力”价值，而不是只评价界面好看；
- 没有用户误认为缺席说明等于补签；
- JSON v2、迁移、删除和隐私文案通过对抗测试。

若两类上下文使用率都低，删除实验，不因已经实现而把它强塞进 Plus。

## 5. R3：2.0 Pulse Plus

只有 R1 留存与 R2 高阶价值均通过，才实现并公开收费。

### 5.1 Plus 首发最小组合

Plus 不能只包含主题和统计图。首发至少同时具备：

1. **节律实验室**：28/90/365 天滚动节律、回归间隔、星期与时间分布；
2. **个人印期**：一个当前印期、历史阶段归档、阶段结业回顾和阶段比较；
3. **持续回响**：每周与每月生成新的本地回顾，用户可编辑和导出；
4. **私密自动同步**：iPhone/iPad 离线可写、恢复可解释、可关闭；
5. **高级档案**：年度几何档案、阶段卡和高分辨率/PDF 导出。

### 5.2 StoreKit 实施

- 一个权益组 `Pulse Plus`，年付与永久版授予相同能力；
- 产品 ID、权益映射、文案和测试 fixture 集中管理；
- 价格从 StoreKit 读取，不硬编码；
- 付费页必须展示核心免费能力不会消失；
- 提供试用条款、自动续期说明、隐私、使用条款、恢复购买和管理订阅；
- 验证购买中断、待处理、取消、退款、撤销、过期、离线启动和商品加载失败；
- Entitlement 变化触发 FeatureAccessPolicy 刷新，但不删除用户内容。

### 5.3 同步原型门禁

在接入生产数据前，用独立 container 和 fixture 证明：

- 两设备离线同日签到最终只有一个业务事实；
- 一端删除、另一端离线编辑上下文的冲突结果明确；
- 时区变更、名称变更和印期结业有稳定顺序；
- 删除使用 tombstone 传播，不因旧设备回连复活；
- iCloud 未登录、配额不足、网络中断、账户切换和服务故障均不阻塞本地签到；
- 每次同步可展示状态、最后成功时间和可重试错误；
- 关闭 Plus 或订阅过期时，所有已同步内容保留本地且可导出。

不得使用“最后写入获胜”作为所有对象的通用兜底。签到事实、可编辑注释、设置和删除需要不同冲突规则。

### 5.4 Plus 上线门禁

- StoreKit Configuration、Sandbox、TestFlight 和生产商品审核链均通过；
- 同步完成 30 天双设备内部试用，无 P0 数据事故；
- 订阅持续价值、到期语义和退款处理通过产品评审；
- 隐私政策、App Privacy、支持站点和商店截图已更新；
- 付费功能无远程服务时仍有清晰降级，免费签到永远不被阻断。

## 6. R4：2.1 随身入口

### 6.1 Apple Watch

- 今日状态、主承诺、签到与最近节律；
- complication / Smart Stack 只显示最小私密信息；
- Watch 离线签到使用稳定操作 ID，回连后幂等合并；
- Watch 与 iPhone 同时签到不重复、不报假失败；
- 触觉、Always-On、Dynamic Type 与电量影响单独验收。

### 6.2 高级 Widget、Control 与 Shortcuts

- 免费基础 Widget 保持；Plus 增加节律、印期和外观配置；
- Control Center / Action Button 操作必须复用同一签到命令；
- App Intents 不暴露备注、缺席原因等私密内容给系统建议；
- Shortcuts 默认动作只读取今日状态或签到，不提供补签日期参数。

### 6.3 继续门槛

- Plus 活跃用户中至少 20% 每周使用 Watch 或高级 Widget；
- 若平台入口使用率低于维护成本，保留基础能力，不继续扩展复杂表盘与自动化矩阵。

## 7. R5：3.0 个性智能

本阶段的“智能”先来自用户自己的结构化数据，不默认上传到远程模型。

### 7.1 可进入实验的能力

- 用户自选最多 3 个观察维度，如精力、专注、场景；
- 本地计算相关性、样本数和不确定性；
- 用“在你的记录中观察到”而不是“你应该”表达；
- 用户能查看证据日期、关闭某个维度、删除全部派生结果；
- 可选的本地语言模型只负责改写用户已经确认的回顾，不生成医疗、心理或行为处方。

### 7.2 禁止进入生产的捷径

- 没有样本量提示的因果结论；
- 把相关性写成建议或诊断；
- 默认上传全部签到与注释；
- 用生成式文案掩盖统计结果为空；
- 远程模型失败时伪造“本地分析”结果。

## 8. 跨阶段工程规则

### 8.1 版本与迁移

- 1.0 发布后，每个 SwiftData / JSON schema 变化都新增显式版本、上一公开版 fixture 和升级/回滚测试；
- 不为未来猜测预埋无消费者字段；需要时再以受控迁移加入；
- App、Widget、Watch、导入和同步都消费同一领域合同，不能各自解释逻辑日。

### 8.2 权威写入

- 所有签到、注释、印期、时区和删除写入经正式 Repository / command service；
- Widget、Watch、Shortcut 和 Cloud 回放是新的调用端，不是新的业务真源；
- 派生洞察可缓存以改善性能，但缓存必须有源版本、可丢弃和可重建，不能反向覆盖事实。

### 8.3 发布状态

每个阶段分别报告：

- engineering_status；
- product_status；
- visual_status；
- device_status；
- privacy/security_status；
- monetization_status；
- release_status。

自动化通过只证明工程门禁，不替代真实用户价值、付费意愿、真机、视觉、同步或商店审核。

## 9. 最近三个可执行里程碑

### 里程碑 A：1.0 Release Candidate

- 只关闭现有发布门禁；
- 产物：真机证据、Archive/TestFlight、商店与支持材料、连续使用报告；
- 决策：公开发布 GO / NO-GO。

### 里程碑 B：1.1 设计合同

- 在编码前新增主承诺命名、隐私锁、Widget/App Group 迁移的产品、领域、技术和测试设计；
- 产物：更新后的 PRD、领域合同、迁移设计、测试矩阵和 Widget 线框；
- 决策：是否进入 1.1 实现。

### 里程碑 C：14 天留存实验

- 招募目标用户，使用免费 1.0/1.1；
- 只收集 App Store Connect 聚合与用户主动分享的本地测试快照；
- 产物：留存、回归、访谈和功能请求排序；
- 决策：R2 GO、修正定位，或停止扩展。
