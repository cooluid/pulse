# 一日一印（Pulse）1.0 之后开发路线图

文档版本：0.6<br>
状态：Proposed Execution Plan，不改变 1.0 已冻结范围  
评审日期：2026-08-11

本计划落实 [PRODUCT_STRATEGY_2_X.md](./PRODUCT_STRATEGY_2_X.md)。原则是一次只验证一个最大风险：先发布可靠性，再验证留存，再建立可收费价值，最后扩大平台与智能能力。

## 1. 总体顺序

| 阶段 | 目标 | 商业状态 | 进入下一阶段的必要证据 |
| --- | --- | --- | --- |

任何阶段都不得绕过前一阶段的证据门禁。路线图不是发布日期承诺。

## 2. R0：关闭 1.0 发布门禁

### 2.1 范围

本阶段不加入 Widget、StoreKit、CloudKit、备注、补签或多项目。

按当前发布合同完成：

1. 正式 Bundle ID 的真实 iPhone 全新安装、签到、重启、删除、清除和触觉验证；
2. 真机通知授权、拒绝、系统外撤权、改时、签到后取消和重启行为；
3. 真实 iPad 横竖屏、分屏和持久化；
4. VoiceOver、最大字号、三种主题、双语、高对比度、降低透明度和 Reduce Motion；
5. 当前源码与 AppIcon Default / Dark / Tinted 最终视觉验收；
6. 签名 Archive、TestFlight 安装、升级与 JSON 恢复；
7. 复核已公开隐私政策与支持页在真实网络和设备上可达，并完成 App Store Connect 链接、商店文案和截图；
8. 跨多个自然日内部使用。

### 2.2 仓库边界决策

发布合同已经记录公开隐私政策与产品支持 URL，但当前 `site/` 源码仍是独立、未提交的嵌套 Git 工作区。发布前必须明确二选一：

- 作为独立站点仓库管理、构建、部署，并在主项目只记录正式 URL；或
- 清除其嵌套仓库边界后，作为主仓受控目录纳入版本管理。

在用户明确决定前，不移动、不合并、不删除该目录。还需用真实设备确认公开 URL 可达、部署内容与受控源码一致、联系邮箱可用，并在 App Store Connect 使用同一 URL；自动化访问被边缘防护拦截不能单独证明普通用户不可访问，也不能替代真机验证。

### 2.3 退出标准

- `RELEASE_SCOPE_1_0.md` 第 6 节全部通过；
- `IMPLEMENTATION_STATUS.md` 的发布结论改为 GO 有对应证据，不只改文字；
- 没有 P0/P1 数据、通知、无障碍或签名问题；
- 已建立真实版本的升级基线 fixture，后续 schema 变化不再 clean-break。

## 3. R1：个性与日印仪式基础

### 3.1 产品范围

#### A. 主承诺身份，免费（已受控前移至首个公开版本）

- 首次启动先让用户确认主承诺名称，不强迫选择模板；默认值仍可一键继续。
- 可选填写一句“为什么重要”，不参与统计，不上传。
- 设置中提供正式重命名入口，变更不改写历史签到事实。
- 今日页把主承诺名称与可选说明放入“保持自己的节奏，不与别人比较”的节奏区，强化“这一枚是为了什么”；不得把承诺作为日期与签到之前的第二个页面标题，也不能挤压主操作和辅助功能。

个人开发账号审核期间，用户已明确授权先推进产品级功能开发。该能力因此通过 `PRODUCT_REQUIREMENTS.md`、`DOMAIN_CONTRACT.md`、`RELEASE_SCOPE_1_0.md`、迁移设计和测试矩阵受控进入首个公开版本，不再作为未落地的 1.1 候选；Widget、Live Activity 与隐私锁仍保持后续边界。

#### B. 基础 Widget，免费

- Lock Screen 圆形只显示今日空心/实心印记，矩形显示最近七日脉冲，默认不泄露主承诺文本；
- Home Screen 小号显示日期、今日状态和签到按钮，中号显示主承诺与七日节律；
- 未签到交互使用只创建事实的 `Button`，不使用可以反向删除记录的 `Toggle`；
- 交互签到必须与 App 内签到走同一业务实现；若共享存储迁移未完成，只允许打开 App，不写第二份状态。

App Group、共享 store 搬迁、跨进程写入、Widget 隐私和能力准入统一执行 [WIDGET_SHARED_STORE_CONTRACT.md](./WIDGET_SHARED_STORE_CONTRACT.md)。账号审核期间先完成可进入 App 正式路径的 Repository 竞争回读和共享核心准备；没有正式 group entitlement 与 provisioning 证据前，不创建依赖 fallback 的生产 Widget target。

#### C. 基础日印仪式，免费

- App 内签到成功沿用“空心印记收缩为一点，再形成实心印记”的落印语言；该窄切片已受控前移至首个公开版本，不包含系统扩展；
- 用户开启系统仪式且平台可用时，签到写入过程可启动短暂 `DailyImprintActivity`，只有 Repository 保存成功或幂等回读后才显示实心落印；
- 回归与第 7、30、100、365 枚只改变正常签到后的两秒动效，不另发通知、不创造徽章真源；
- 本阶段不做远程自动启动、不占用灵动岛全天、不把落印动画当作签到成功依据；
- 所有触发、措辞、动效、隐私和降级以 [PULSE_RITUAL_CONTRACT.md](./PULSE_RITUAL_CONTRACT.md) 为准。

#### D. 隐私与反馈

- App 切回前台的可选 Face ID / Touch ID 锁；隐私锁免费；
- TestFlight 提供“分享测试快照”，用户预览后主动发送本地聚合，不附原始日期与文字；
- 在用户积累足够体验、且最近一次关键操作成功后才请求系统评分，不在首次启动请求。

### 3.2 技术准备

- 在领域合同中增加“重命名不影响事实”的规则，再增加 Repository 写入方法与测试；
- 为 Widget 建立 App Group store 迁移设计与中断恢复测试；
- 已抽取 extension-safe 静态 `PulseCore`，当前 App 已只链接这一份领域、schema、Repository、验证和导入导出实现；Widget / Live Activity 后续必须消费同一模块，所有写入仍由正式 Repository / command service 所有；
- 建立一个 Widget extension 承载 Widget 与 Live Activity 布局，但分别维护长期 timeline 和短期 ActivityKit 生命周期；
- 增加跨进程同日并发写入测试，唯一冲突必须回读现有记录并幂等成功；
- Widget / Live Activity 刷新失败只影响展示，不反向覆盖主 store；
- 动效参数集中定义，覆盖两秒上限、Reduce Motion、Always-On 静态表达和系统压缩呈现。

### 3.3 验收

- 旧 1.0 store 升级后事实、时区、设置和 JSON 导出均一致；
- App 未运行、设备锁定、Widget 重载、快速双击和 App/Widget 同时签到不产生重复；
- 隐私锁不阻止通知协调和 Widget 的非敏感状态；
- 保存失败时 App、Widget 和 Live Activity 都不显示实心落印；有无灵动岛、Always-On 与 Reduce Motion 的表达语义一致；
- 真实设备逐帧验收落印、回归和里程碑动效，确认舒服、可读、无闪烁且不会强迫用户看向灵动岛；
- D7 / D28 和 14 天快照达到战略文档初始门槛，或形成明确的修正结论。

## 4. R2：1.2 真实上下文与回归实验

本阶段先在 TestFlight 免费验证，不立即收费。

### 4.1 数据合同

新增 `DayAnnotation`，与 `CheckInRecord` 分离：

- `annotationKey = lowercased(habitID) + ":" + logicalDay`；
- 同一主承诺、同一逻辑日最多一个上下文对象；
- 支持短文本回响、是否值得记住、预定义缺席原因；
- 注释可存在于已签到日或已过去的缺席日；
- 注释永远不能创建、补写或延续签到事实；
- 未来日期不能写缺席原因；今天在日界线结束前不能标记为缺席；
- 删除签到与删除注释分开确认；JSON schema 新版本明确导出和恢复注释。

不在首个实验加入照片、自由标签系统或 AI。

### 4.2 产品实验

#### A. 三秒回响

签到成功后提供一个可跳过的轻量入口：一句话或一个“值得记住”标记。它不能阻塞两秒签到主流程，也不能每次弹出强制 Sheet。

#### B. 真实缺席说明

过去的缺席日可选择“休息、旅行、身体状态、忘记、其他”等少量原因并写一句说明。月历仍明确显示未签到，统计不因此增加。

#### C. 回归力原型

只从签到事实派生：

- 中断次数；
- 中断后 1/3/7 天内回归比例；
- 当前恢复阶段；
- 最近 28 天完成率。

措辞必须描述事实，不做心理、医疗或人格诊断。

### 4.3 继续门槛

- 至少 30 个用户完成 14 天实验；
- 至少 30% 的实验用户在 14 天内写入 5 次以上三秒回响，或至少 30% 的发生缺席用户使用缺席说明；
- 访谈能复述“回归力”价值，而不是只评价界面好看；
- 没有用户误认为缺席说明等于补签；
- JSON v2、迁移、删除和隐私文案通过对抗测试。

若两类上下文使用率都低，删除实验，不因已经实现而把它强塞进 Plus。

## 5. R2.5：1.3 影像印记实验

本阶段只验证“签到后可选留下一张今天”是否形成长期价值，不提前收费，也不承诺生成最终面貌影片。它必须在 R2 结论明确后独立进入 TestFlight，不能混进首个上下文实验导致无法判断留存变化来自哪里。

### 5.1 产品范围

#### A. 今日影像，免费实验

- `CheckInRecord` 保存成功并展示签到成功后，才出现可跳过的“留一张今天”；
- 相机授权只在用户主动点击拍摄时请求；拒绝、取消、保存失败或照片不合格都不能撤销签到；
- 同一主承诺、同一逻辑日最多保留一张正式今日影像；用户在日界线前可以重拍，替换前保留旧文件直至新文件和元数据同时提交成功；
- 前后摄像头均可使用，面孔、环境、宠物等都能成为今日影像；用户可关闭当天提示或永久关闭入口；
- 查看、删除和原图导出属于免费数据控制能力，不因 Plus 状态变化。

#### B. 岁月面貌采集，免费实验

- 仅对用户主动选择的单人正面照片执行本地人脸关键点和质量判断；
- 提供面部轮廓、眼睛对齐、距离、角度、清晰度和光线提示，并可选显示上一张合格照片的低透明度参考；
- 不合格照片仍可作为今日影像保存，只标记为暂不进入岁月影片，不以容貌语言批评用户；
- 不进行年龄、性别、颜值、健康或身份推断，不保存关键点、特征向量或质量分析中间结果。

#### C. 签到后今日影像窗口，免费实验

- 只有签到成功且用户已启用影像邀请时，`DailyImprintActivity` 才从“已落印”转入 5 分钟影像窗口；
- Compact 只显示抽象印记与“留一张今天”，Expanded / Lock Screen 只提供打开今日相机的一个主要操作；
- 拍照、跳过、关闭或超时后立即结束，当天不再单独追发拍照提醒；
- 灵动岛、锁屏、StandBy、Watch 和 Mac 默认不显示真实照片、文件名、地点或人脸分析结果。

### 5.2 数据与恢复门禁

- 新增独立 `ImprintMedia`，关联 `recordID` 和逻辑日，但不参与签到、连续天数和统计；
- SwiftData 只保存媒体元数据与相对路径，原图、缩略图和导出缓存由唯一文件仓储管理，不把大图片 Blob 写入主 store；
- 删除照片不删除签到；删除签到时单独确认相关媒体；清除全部数据必须删除媒体、缩略图、临时文件和生成缓存；
- JSON 继续承担结构化事实导出，不能声称包含原图。进入生产前新增版本化 Pulse 归档包，包含 manifest、结构化记录和媒体，并验证校验值、空间不足、中断恢复和损坏失败关闭；
- 文件落盘、元数据提交和替换使用显式事务顺序，并提供启动时孤立文件审计，不能用“稍后清理”掩盖丢图或泄漏。

### 5.3 继续门槛

- 至少 30 个用户完成 14 天实验；
- 至少 30% 主动启用，启用者 14 天拍摄中位数达到 8 天；
- 未启用影像的核心签到仍在两秒内完成，拍摄邀请不降低签到完成率；
- 没有丢图、替换失败误删、孤立文件、缩略图泄漏或恢复不完整的 P0 事故；
- 用户能理解这是长期面貌记录，不是年龄检测、颜值评估或每日衰老指数；
- 真实照片在眼镜、发型、表情、光线和间隔变化下仍有足够比例通过采集门槛。

任一数据完整性门禁失败都先修复媒体生命周期；使用率不足则删除实验，不因为已经实现相机功能就推进动画或收费。

## 6. R3：2.0 Pulse Plus

只有 R1 留存与 R2 高阶价值均通过，才实现并公开收费。

### 6.1 Plus 首发最小组合

Plus 不能只包含主题和统计图。首发至少同时具备：

1. **节律实验室**：28/90/365 天滚动节律、回归间隔、星期与时间分布；
2. **个人印期**：一个当前印期、历史阶段归档、阶段结业回顾和阶段比较；
3. **持续回响**：每周与每月生成新的本地回顾，用户可编辑和导出；
4. **私密自动同步**：iPhone/iPad 离线可写、恢复可解释、可关闭；
5. **高级档案**：年度几何档案、阶段卡和高分辨率/PDF 导出。

### 6.2 StoreKit 实施

- 一个权益组 `Pulse Plus`，年付与永久版授予相同能力；
- 产品 ID、权益映射、文案和测试 fixture 集中管理；
- 价格从 StoreKit 读取，不硬编码；
- 付费页必须展示核心免费能力不会消失；
- 提供试用条款、自动续期说明、隐私、使用条款、恢复购买和管理订阅；
- 验证购买中断、待处理、取消、退款、撤销、过期、离线启动和商品加载失败；
- Entitlement 变化触发 FeatureAccessPolicy 刷新，但不删除用户内容。

### 6.3 远程留印窗口原型

远程自动启动不复用本地通知假装完成。用独立开发环境证明：

- 用户主动开启后，App 获取并轮换 ActivityKit push-to-start token，后端在提醒时刻通过 APNs 启动 10/20/30 分钟的 `ReminderWindow`；
- 每个项目、逻辑日最多自动启动一次，用户关闭后当天不重启，签到后取消本地通知、远程任务和当前 Activity；
- `ReminderPolicy` 只选择一个主提醒通道；灵动岛不可用或任务未接受时，只有用户同意才回退本地通知，不与微信或本地通知重复发送；
- push token、项目标识、时区、逻辑日、提醒时刻、窗口长度和 revision 是远程上限；不上传照片、注释、主承诺正文和完整签到历史；
- APNs 延迟、重复、乱序、撤权、设备迁移、服务故障和离线签到不会恢复旧窗口或阻塞本地签到；
- 本原型的状态机、每日预算和失败语义以 [PULSE_RITUAL_CONTRACT.md](./PULSE_RITUAL_CONTRACT.md) 为准。

原型通过前不进入付费页或商店承诺。基础本地提醒、Widget 和签到后的免费落印不依赖该后端。

### 6.4 同步原型门禁

在接入生产数据前，用独立 container 和 fixture 证明：

- 两设备离线同日签到最终只有一个业务事实；
- 一端删除、另一端离线编辑上下文的冲突结果明确；
- 时区变更、名称变更和印期结业有稳定顺序；
- 删除使用 tombstone 传播，不因旧设备回连复活；
- iCloud 未登录、配额不足、网络中断、账户切换和服务故障均不阻塞本地签到；
- 每次同步可展示状态、最后成功时间和可重试错误；
- 关闭 Plus 或订阅过期时，所有已同步内容保留本地且可导出。

不得使用“最后写入获胜”作为所有对象的通用兜底。签到事实、可编辑注释、设置和删除需要不同冲突规则。

### 6.5 Plus 上线门禁

- StoreKit Configuration、Sandbox、TestFlight 和生产商品审核链均通过；
- 同步完成 30 天双设备内部试用，无 P0 数据事故；
- 订阅持续价值、到期语义和退款处理通过产品评审；
- 隐私政策、App Privacy、支持站点和商店截图已更新；
- 远程留印窗口完成主动开启、关闭、撤权、每日上限、通道仲裁、服务故障和过期任务验证，不以 APNs 接受代替用户可见；
- 付费功能无远程服务时仍有清晰降级，免费签到永远不被阻断。

## 7. R4：2.1 岁月流影

只有 R2.5 证明用户愿意长期拍摄、媒体可靠性通过，且 R3 的正式权益与退出语义已经上线，才进入本阶段。目标不是照片轮播，而是把所有“合格的岁月面貌照片”按真实日期生成连续、平滑、可解释的面貌变化影片。

### 7.1 渲染范围

按能力递进实现，不一步跳到生成式 AI：

1. **稳定序列**：依据眼睛和面部轮廓统一旋转、缩放、裁切与画布，先消除构图跳动；
2. **面貌融合**：对相邻真实照片执行关键点网格形变与纹理交叉融合，减少双眼、双鼻等重影；
3. **真实时间轴**：按实际日期映射影片进度，明确显示跨日间隔；缺失日期不补造照片，插值帧只作视觉过渡；
4. **档案输出**：提供 30/90/365 天、多年、往年今日和用户自选区间，支持 1080p/4K 导出。
5. **系统进度**：用户离开 App 后，用 `ImprintRenderActivity` 展示 preparing、aligning、blending、encoding 的实际进度、取消、失败和完成摘要。

默认不使用远程生成式模型，不做美颜、年轻化、年龄估算或身份识别。若本地性能不能满足，应先降低分辨率、延长显式渲染时间或暂停功能，不能静默上传人脸作为兜底。

### 7.2 免费与 Plus 边界

- 免费：继续拍摄、查看、删除、导出原图，查看基础对齐序列；
- Plus：自动关键点对齐、网格形变、平滑融合、真实时间轴、往年对比、年度影片和高分辨率导出；
- 权益到期：既有照片和已生成影片保持可读、可删、可导出，只停止新的高级渲染和 Plus 创建；
- 本地渲染本身没有持续服务器成本，不能单独支撑年订阅；永久版继续覆盖本地高级能力，年费价值必须来自持续回响、同步和长期系统维护。

### 7.3 验收门禁

- 在真实用户照片集上覆盖眼镜、发型、胡须、妆容、表情、光线、角度、设备镜头和长时间缺口；
- 逐对检查关键点漂移、五官分裂、背景拉扯、肤色闪烁、帧顺序和日期真实性；
- 标准清晰度与 4K 导出期间，内存峰值、温升、耗电、后台中断、磁盘不足和取消行为均可解释；
- 灵动岛百分比来自实际任务完成量，不使用独立计时器伪造平滑进度；失败、取消和任务恢复不会留下假成品或假完成摘要；
- Reduce Motion 用户可关闭自动播放和形变预览；VoiceOver 能读取日期范围、照片数量和导出状态；
- 自动化只验证顺序、元数据、幂等和编码结果，最终 `visual_status` 必须由真人逐帧与整片验收；
- 至少有用户愿意为融合、年度影片或长期档案付费，而不只是愿意免费拍照。

## 8. WX0：微信提醒资格轨

微信资格轨与产品版本并行，但在通过前不占用正式发布日期，也不进入付费页。iOS 本地提醒始终保留为免费、默认、离线可用的主通道。

### 8.1 资格预检

在编写后端和 App 绑定逻辑前，依次取得：

1. 正式主体及认证服务号、开放平台应用或小程序的可用账号；
2. 与 Pulse 实际业务一致的服务类目；
3. 微信后台可选且审核通过的日常提醒模板；
4. 用户主动授权、拒绝、撤权、退订和重新授权的真机流程；
5. 真实微信账号的一次发送、送达结果、频率限制和投诉风险证据。

服务号模板消息只面向认证服务号的重要服务通知；订阅通知的一次性授权只能发送一条，长期订阅主要面向政务、医疗等公共服务。若普通日签到提醒没有合法模板或长期授权能力，WX0 直接 `NO-GO`，不采用个人号机器人、客户端 Hook、模拟点击、文件传输助手或第三方代发兜底。

### 8.2 通过后的 WX1 工程范围

只有五项资格全部通过，才建立：

- 单一 `ReminderPolicy`，由本地通知、Live Activity 和微信适配器消费同一时区、提醒分钟、启用状态与授权版本；
- 最小后端调度服务，只保存微信侧标识、项目标识、时区、逻辑日、下一次发送、授权版本和发送状态；
- 每个用户、项目、逻辑日、通道唯一的幂等键，防止重复发送；
- 签到、关闭提醒、改时、解绑微信和清除数据对尚未发送任务的取消或替换；
- “已提交、已送达、发送失败、用户拒收”分离状态，不把接口成功伪装成实际送达；
- 服务端凭证管理、日志脱敏、数据导出、解绑删除、限流、重试、监控和应急停发。

服务器不接收面貌照片、注释正文或完整签到历史。离线签到使取消尚未同步时，微信可能发出过期提醒；若无法把这个边界解释清楚并控制在可接受水平，就不进入生产。

### 8.3 商业与发布门禁

- 微信提醒只能作为可选增强通道，失败不得关闭本地提醒或阻塞签到；
- 在取得真实发送成本、送达率、退订率和持续可用性前，不承诺属于年付或永久权益，也不定价；
- 隐私政策、App Privacy、微信侧授权说明、服务端删除和支持流程全部更新；
- 至少完成授权、拒绝、撤权、重复回调、签到竞态、改时、跨日、离线和服务故障测试；
- 平台资格变化可远程停止新绑定和发送，但不能影响用户本地数据与本地提醒。

## 9. R5：2.2 随身入口

### 9.1 W0：Watch 可行性门禁

R1 的统一签到命令与 App Group 迁移稳定后即可提前启动 W0，不必等到 R5；但 W0 不进入生产历史，正式 Watch 发布仍须通过 R5 门禁。候选基线为 watchOS 10：

- 验证 Watch App、WidgetKit complication、Smart Stack，以及 watchOS 11 及以后 iPhone Live Activity 在 Watch 上的真实布局；
- 验证即时消息、latest application context 与保证排队的后台用户信息，不把模拟器结果当作连接可靠性证据；
- 记录 iPhone/Watch 前后台、强退、重启、断联、飞行模式、蓝牙/Wi-Fi 切换与重新配对结果；
- 在 `DOMAIN_CONTRACT.md` 冻结延迟命令跨午夜、项目时区变化和旧项目 revision 的裁决语义；
- 确定 Watch 本机 snapshot/outbox、Widget extension App Group、Bundle ID、签名、隐私和最低版本矩阵；
- W0 不创建第二份业务 store，不把原型命令写入生产签到历史。

### 9.2 Watch v1 免费基础

- Watch App 今日页：抽象印记、可隐藏主承诺、今日状态、一个大签到按钮和最近七日脉冲；
- 免费 complication：圆形空心/实心印记、矩形今日状态或七日脉冲；
- 免费 Smart Stack：今日状态和一个签到动作；系统决定实际相关性排序，不承诺到点必然置顶；
- watchOS 11 及以后把 iPhone `DailyImprintActivity` 复用到 Watch Smart Stack，并提供必要的 Watch 专用紧凑布局，不复制第二条 Watch Live Activity；watchOS 10 明确回退普通 Smart Stack Widget；
- 今日影像只提示回到 iPhone 拍摄，Watch 不展示面孔、不声称能远程打开 iPhone 相机；
- 基础 Watch App、基础 complication、Smart Stack 与可靠签到不能因为维护成本被放入 Plus。

### 9.3 Watch 命令、离线与确认

- iPhone 正式 store 仍是唯一真源；Watch 只保存可重建快照和 durable command outbox；
- Watch 点击后创建稳定 `operationID` 的 `WatchCheckInCommand`，不直接创建 `CheckInRecord`；
- 可达时用即时消息加速，不可达或超时时用后台排队传输；两者携带同一命令并进入同一 iPhone command service；
- latest application context 只同步今日状态等最新快照，不能承担可能被覆盖的动作；
- UI 必须明确区分 `正在确认`、`已记录，等待同步`、`今天已落印` 和 `未保存`；等待同步不得使用成功勾号、实心印记或成功触觉；
- iPhone 回执携带操作 ID、正式逻辑日、记录时间/标识和结果；只有回执确认新建或幂等命中后才清除 outbox；
- Watch 与 iPhone、Widget、Live Activity 同时签到，以及命令重复、迟到和乱序，最终仍只有一条正式记录；
- Watch 不提供补签日期、删除或修改签到时间。

### 9.4 Watch Plus 高阶价值

- 28/90/365 日节律、回归力、个人印期、年轮与往年今日抽象回看；
- 用户可分别决定主承诺、连续天数和长期节律是否进入表盘或 Smart Stack；
- 不按表盘家族、尺寸或颜色重复收费，不出售“Watch 皮肤包”；
- Plus 到期后基础 Watch 签到保持可用，既有签到事实和快照可继续读取；
- 先证明基础 Watch 每周使用与可靠性，再建设复杂表盘矩阵，不能把低采用率解释成付费墙问题。

### 9.5 高级 Widget、Control 与 Shortcuts

- 免费基础 Widget 保持；Plus 增加 28/90/365 日节律、回归力、印期、年轮、往年今日和显式隐私配置，不按 Widget 尺寸收费；
- Control Center / Action Button 操作必须复用同一签到命令；
- App Intents 不暴露备注、缺席原因等私密内容给系统建议；
- Shortcuts 默认动作只读取今日状态或签到，不提供补签日期参数；
- Widget、Control、Action Button、Shortcuts、Watch 和 Live Activity 的动作语言、敏感信息、通道仲裁与状态解释以 [PULSE_RITUAL_CONTRACT.md](./PULSE_RITUAL_CONTRACT.md) 为准。

### 9.6 继续门槛

- 至少 30 名配对真机用户完成 14 天测试，零重复记录、错误成功、静默错日和同义重复提醒；
- Watch 已启用用户中至少 30% 每周使用基础 Watch App、complication 或 Smart Stack；
- Plus 活跃用户中至少 20% 每周使用 Watch 高级节律或高级 Widget，才继续扩展付费表面；
- 后台排队传输、即时回执与离线恢复在真实配对设备通过，且 `pendingSync` 被用户正确理解；
- complication、Smart Stack、Watch App，以及 watchOS 11+ 的 Live Activity 布局，在 Always-On、Dynamic Type、VoiceOver、Reduce Motion 和锁定隐私下完成视觉验收；
- 14 天电量观察不出现高频刷新、持续动画或连接轮询导致的异常消耗；
- 若平台入口使用率低于维护成本，保留基础能力，不继续扩展复杂表盘与自动化矩阵。

## 10. R6：3.0 个性智能

本阶段的“智能”先来自用户自己的结构化数据，不默认上传到远程模型。

### 10.1 可进入实验的能力

- 用户自选最多 3 个观察维度，如精力、专注、场景；
- 本地计算相关性、样本数和不确定性；
- 用“在你的记录中观察到”而不是“你应该”表达；
- 用户能查看证据日期、关闭某个维度、删除全部派生结果；
- 可选的本地语言模型只负责改写用户已经确认的回顾，不生成医疗、心理或行为处方。

### 10.2 禁止进入生产的捷径

- 没有样本量提示的因果结论；
- 把相关性写成建议或诊断；
- 默认上传全部签到与注释；
- 用生成式文案掩盖统计结果为空；
- 远程模型失败时伪造“本地分析”结果。

## 11. 跨阶段工程规则

### 11.1 版本与迁移

- 1.0 发布后，每个 SwiftData / JSON schema 变化都新增显式版本、上一公开版 fixture 和升级/回滚测试；
- 不为未来猜测预埋无消费者字段；需要时再以受控迁移加入；
- App、Widget、Watch、导入和同步都消费同一领域合同，不能各自解释逻辑日。
- Widget、Live Activity、Control、Action Button 和 Watch 的系统表面语义只在 [PULSE_RITUAL_CONTRACT.md](./PULSE_RITUAL_CONTRACT.md) 定义，其他阶段不复制状态机。

### 11.2 权威写入

- 所有签到、注释、媒体、印期、时区、提醒策略和删除写入经正式 Repository / command service；
- Widget、Watch、Shortcut 和 Cloud 回放是新的调用端，不是新的业务真源；
- 派生洞察可缓存以改善性能，但缓存必须有源版本、可丢弃和可重建，不能反向覆盖事实。

### 11.3 发布状态

每个阶段分别报告：

- engineering_status；
- product_status；
- visual_status；
- device_status；
- privacy/security_status；
- monetization_status；
- release_status。

自动化通过只证明工程门禁，不替代真实用户价值、付费意愿、真机、视觉、同步或商店审核。
