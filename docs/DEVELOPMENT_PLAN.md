# Pulse 日签到开发计划

文档版本：1.0  
计划口径：单人开发、已有 SwiftUI 基础、未包含正式视觉设计和 App Store 审核时间

## 1. 总体策略

开发顺序遵循依赖关系：先锁定日期与持久化，再做页面，最后做提醒和发布增强。

不建议先画完整 UI 再补数据层。签到项目最难的不是按钮，而是跨日、时区、幂等和统计；如果这些规则后置，界面会建立在错误状态模型上。

## 2. 里程碑总览

| 里程碑 | 目标 | 预计投入 | 结果 |
| --- | --- | --- | --- |
| M0 工程基础 | 建立测试和环境基线 | 0.5–1 人日 | 可持续开发的工程骨架 |
| M1 领域与数据 | 跑通可靠签到事实链 | 1.5–2 人日 | 可测试、可持久化的签到内核 |
| M2 今日页 | 完成核心签到体验 | 1–1.5 人日 | 用户可完成每日签到 |
| M3 历史与统计 | 完成月历和连续天数 | 1.5–2 人日 | 用户可理解历史与趋势 |
| M4 设置与提醒 | 完成 P0 设置和 P1 提醒 | 1–1.5 人日 | 可配置、可提醒、可清理 |
| M5 质量与发布准备 | 真机、无障碍、迁移和回归 | 1.5–2 人日 | 工程候选版本 |

核心 MVP 预计约 7–10 人日。该估算不是发布日期承诺；正式视觉、CloudKit、商店素材和审核另计。

## 3. M0：工程基础

### 任务

- `FND-001` 决定最低系统版本，公开发布建议 iOS / iPadOS 17.0+。
- `FND-002` 创建 `pulseTests` 单元测试 target。
- `FND-003` 创建 `pulseUITests` UI 测试 target。
- `FND-004` 建立 SwiftData schema 和内存测试容器。
- `FND-005` 建立 `AppEnvironment`，注入 Clock、Repository 和设置存储。
- `FND-006` 配置 Debug / Release 构建检查。
- `FND-007` 确认 iPhone 与 iPad 是否都作为正式验收平台。

### 完成门槛

- 空白单元测试和 UI 测试均可运行。
- App 在选定最低系统版本模拟器上启动。
- 测试可以使用内存 SwiftData 容器，不污染开发数据。
- 不再在 `ContentView` 内直接承载所有业务依赖。

## 4. M1：领域与数据

### 任务

- `DOM-001` 实现 `LogicalDay`。
- `DOM-002` 实现固定时区和日界线计算。
- `DOM-003` 实现 `Clock`、`SystemClock` 和 `FixedClock`。
- `DOM-004` 实现当前连续、最长连续和累计统计。
- `DAT-001` 实现 `Habit` 和 `CheckInRecord` SwiftData 模型。
- `DAT-002` 实现稳定 `recordKey` 工厂与唯一约束。
- `DAT-003` 实现默认项目初始化。
- `DAT-004` 实现 Repository 查询、签到、删除和清空。
- `DAT-005` 覆盖持久化失败和重复签到行为。

### 完成门槛

- `DOMAIN_CONTRACT.md` 的逻辑日和统计样例全部有单元测试。
- 同一天并发或快速重复请求只返回一条记录。
- App 重启后记录仍存在。
- 保存失败不会生成成功状态。
- 数据层 API 不接受任意历史日期补签。

## 5. M2：今日页

### 任务

- `TOD-001` 实现 TodayViewModel 状态机。
- `TOD-002` 实现今日日期和签到主按钮。
- `TOD-003` 实现保存中、成功和失败状态。
- `TOD-004` 实现最近 7 天概览。
- `TOD-005` 实现当前连续天数展示。
- `TOD-006` 实现触觉反馈和 Reduce Motion 兼容。
- `TOD-007` 监听 scene active、系统显著时间变化和前台跨日。
- `TOD-008` 编写首次启动、签到和重启恢复 UI 测试。

### 完成门槛

- 用户能在两秒内完成签到。
- 快速连点不会重复保存。
- 前台和后台跨日后均自动显示正确状态。
- 错误提示可恢复，界面不会卡在保存中。
- 动态字体和 VoiceOver 下主操作可用。

## 6. M3：历史与统计

### 任务

- `HIS-001` 实现月历网格和月份切换。
- `HIS-002` 实现创建前、已签到、漏签、今日和未来状态。
- `HIS-003` 实现日期详情。
- `HIS-004` 实现累计、当前连续和最长连续统计卡片。
- `HIS-005` 实现删除记录与二次确认。
- `HIS-006` 删除后统一刷新今日页和历史页。
- `HIS-007` 编写月首、月末、闰年和删除回归测试。

### 完成门槛

- 月历分类与业务规则完全一致。
- 未来日期不可签到，空白历史日期不可补签。
- 删除一条记录后所有统计正确重算。
- 不通过缓存字段维护连续天数。

## 7. M4：设置与提醒

### P0 任务

- `SET-001` 实现触觉反馈设置。
- `SET-002` 展示当前签到时区。
- `SET-003` 实现清除全部数据和二次确认。
- `SET-004` 展示 App 版本。

### P1 任务

- `REM-001` 实现提醒开关和时间选择。
- `REM-002` 只在用户主动开启时请求通知权限。
- `REM-003` 实现未来 30 天滚动通知窗口。
- `REM-004` 签到成功后取消当天待发送通知。
- `REM-005` 覆盖允许、拒绝、系统设置关闭和重新授权。
- `EXP-001` 实现带 schema 版本的 JSON 导出。
- `SET-005` 实现签到时区修改提示和刷新。

### 完成门槛

- 清空后记录、设置和 App 创建的通知都被清理。
- 通知权限拒绝不影响签到。
- 当天已签到后不再发送当天提醒。
- 导出文件可以被解析，数量和日期与 App 内一致。

## 8. M5：质量与发布准备

### 任务

- `QA-001` 执行完整自动化测试。
- `QA-002` iPhone 真机签到、重启、通知和跨日验证。
- `QA-003` iPad 真机或对应模拟器布局验证。
- `QA-004` 深色模式、动态字体、VoiceOver 和 Reduce Motion 验证。
- `QA-005` Debug 与 Release 构建。
- `QA-006` 使用旧 schema fixture 做迁移演练。
- `QA-007` 验证无网络时完整核心流程。
- `REL-001` 确认 App 名称、图标、Bundle ID 和版本号。
- `REL-002` 确认隐私说明和数据丢失边界。
- `REL-003` 决定 CloudKit 或导出恢复是否为发布阻塞项。

### 完成门槛

- [TEST_PLAN.md](./TEST_PLAN.md) 中所有 P0 用例通过。
- 没有阻断签到、丢失记录或错误统计的已知缺陷。
- Release 构建不依赖测试数据或 Debug 开关。
- 工程完成、视觉验收、真机验收和发布政策分别给出结论。

## 9. 推荐迭代拆分

### Iteration 1：可验证的签到内核

范围：M0 + M1。  
交付：没有正式 UI，但可以通过测试证明日期、唯一性、持久化和统计正确。

### Iteration 2：核心可用版本

范围：M2 + M3 + P0 设置。  
交付：完整本地日签到 MVP。

### Iteration 3：首个增强版本

范围：P1 提醒、导出、时区设置和发布准备。  
交付：更适合长期使用或对外测试的版本。

## 10. 风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 设备时区变化 | 同一天重复或日期跳变 | 项目时区固定持久化 |
| SwiftData 唯一写入行为处理不当 | 重复记录或保存错误 | 串行 Repository + 唯一约束 + 测试 |
| 只在启动时判断日期 | 前台跨日状态错误 | scene、显著时间变化、边界计时器三重刷新 |
| 连续天数缓存 | 删除后统计失真 | 从记录重新计算 |
| 永久重复通知 | 已签到仍提醒 | 滚动一次性通知窗口 |
| 仅本地存储 | 卸载后永久丢失 | 明确告知；P1 导出或后续 CloudKit |
| 最低版本 26.4 | 可安装设备范围过窄 | 开工前决定是否下调到 17.0 |
| iPad 名义支持 | 布局未真正验收 | 将 iPad 纳入测试矩阵或移除设备族 |

## 11. 变更控制

- 新需求必须标明 P0、P1 或 P2。
- 影响日期、唯一性或统计的变更，必须先修改业务规则和测试。
- 不在迭代中途加入账号、CloudKit 或多项目；它们会改变数据所有权和冲突模型。
- 任何任务只有在实现、自动化测试和相应手工验证都完成时才可关闭。
