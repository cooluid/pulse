# Pulse 日签到测试与验收计划

文档版本：1.0  
状态：自动化工程门禁已通过；真机与发布验收待执行

## 1. 测试目标

测试重点不是证明页面能点击，而是证明同一个签到事实在日期变化、快速操作、持久化和统计计算中始终一致。

测试分为：

- 领域单元测试：日期和统计规则。
- 数据层集成测试：SwiftData 唯一性、保存、删除和恢复。
- ViewModel 测试：状态转换和错误恢复。
- UI 自动化测试：核心用户路径。
- 手工与真机测试：通知、无障碍、布局、生命周期和系统行为。

## 2. 测试环境

### 2.1 自动化环境

- 单元测试使用内存 SwiftData container。
- 每个测试创建独立 container，不共享记录。
- 时间使用 `FixedClock`。
- 时区必须显式指定，不能依赖运行测试的 Mac 当前时区。
- Locale 只影响展示测试，不影响逻辑日测试。

### 2.2 建议覆盖设备

- 最小尺寸 iPhone 模拟器。
- 主流尺寸 iPhone 模拟器。
- 大尺寸 iPhone 模拟器。
- iPad 竖屏和横屏。
- 至少一台真实 iPhone，用于通知、触觉、生命周期和持久化。

如果最终下调最低系统版本，还要覆盖最低支持版本和当前最新版本。

| DAY-003 | 年末 12 月 31 日跨年 | 进入下一年 1 月 1 日 |
| DAY-004 | 闰年 2 月 28 日至 29 日 | 日期相邻正确 |
| DAY-005 | 闰年 2 月 29 日至 3 月 1 日 | 日期相邻正确 |
| DAY-006 | 非闰年 2 月 28 日至 3 月 1 日 | 日期相邻正确 |

### 3.2 唯一性和签到

| ID | 场景 | 预期 |
| --- | --- | --- |
| CHK-001 | 空数据库首次签到 | 创建一条记录 |
| CHK-002 | 同日再次签到 | 返回已有记录，总数仍为 1 |
| CHK-003 | 快速发起多次签到 | 总数仍为 1 |
| CHK-004 | 两个不同逻辑日签到 | 存在两条记录 |

| CHK-006 | 保存失败 | 抛出失败，不报告成功 |
| CHK-007 | 请求历史日期签到 | API 拒绝，不创建补签记录 |

### 3.3 连续天数

| ID | 记录情况 | 预期当前连续 |
| --- | --- | --- |
| STR-001 | 无记录 | 0 |
| STR-002 | 仅今天 | 1 |
| STR-003 | 仅昨天，今天未签到 | 1 |
| STR-004 | 前天和昨天，今天未签到 | 2 |
| STR-005 | 昨天漏签，今天已签到 | 1 |
| STR-006 | 连续 30 天含跨月 | 30 |
| STR-007 | 连续跨年 | 正确连续 |
| STR-008 | 中间删除一天 | 连续区间被拆分 |
| STR-009 | 乱序输入和重复日期 | 去重排序后结果正确 |

最长连续和累计签到需覆盖空集合、单条、多段相同长度、删除后重算。

### 3.4 日期分类与完成率

- 项目创建前日期不算漏签。
- 未来日期不算漏签。
- 今天未签到显示待签到，不提前显示漏签。
- 今天已签到计为完成。
- 月中创建项目时，分母从创建日开始。
- 查询未来月份时完成率无有效分母，不显示误导性的 0%。

发布第二个 schema 版本前，必须新增旧 schema 到新 schema 的迁移测试。

## 5. ViewModel 测试

### TodayViewModel

- 加载时从 Repository 得到正确今日状态。
- `available → saving → checked` 只在保存成功时发生。
- 保存失败进入失败提示并恢复可操作。
- saving 状态下再次触发不会重复调用 Repository。
- Scene 重新 active 时跨日刷新。
- 删除今天记录后状态变为 available。

### HistoryViewModel

- 月份前后切换生成正确网格。
- 日期分类与领域规则一致。
- 删除成功后统计和网格同步更新。
- 删除失败时保留原有展示并提示错误。

## 6. UI 自动化测试

P0 自动化路径：

1. `UI-001` 首次启动显示“今日签到”。
2. `UI-002` 点击签到后显示“今日已签到”和时间。
3. `UI-003` 终止并重启 App，仍显示今日已签到。
4. `UI-004` 连续快速点击不会出现重复计数。
5. `UI-005` 记录页显示今天已签到。
6. `UI-006` 删除今天记录后，今日页恢复未签到。
7. `UI-007` 清除全部数据后回到空状态。
8. `UI-008` 未来日期不可操作。
9. `UI-009` 空白历史日期没有补签入口。
10. `UI-010` 月历始终呈现 7 个星期标题，重复的 T / S 不发生身份冲突。

UI 测试应通过 launch arguments 使用独立测试数据容器和固定时钟，不能依赖测试当天的真实日期。

## 7. 手工与真机测试

### 7.1 生命周期

- 前台停留跨零点。
- 后台跨零点后返回。
- 手动修改系统时间后返回 App。
- 手动修改系统时区后返回 App。
- 系统杀死 App 后重新启动。
- 低电量模式下完成签到。

### 7.2 通知（P1）

- 首次启动不请求通知权限。
- 主动开启提醒后才请求权限。
- 允许权限后按设定时间收到通知。
- 拒绝权限后签到功能正常。
- 从系统设置关闭权限后，App 显示真实状态。
- 当天签到后，当天未发送提醒被取消。
- 修改提醒时间后旧请求清除，新请求正确。
- 清空数据后 Pulse 创建的通知全部取消。
- 点击通知进入今日页。

### 7.3 可访问性与视觉

- 浅色和深色模式。
- 高对比度和降低透明度。
- Reduce Motion 开启时无必要的大幅动画。
- 动态字体从默认到无障碍超大字号。
- VoiceOver 按合理顺序读取今日页。
- 月历每个日期能读出“日期 + 状态”。
- iPhone 横竖屏策略符合产品决定。
- iPad 分屏、竖屏和横屏无内容截断。
- AppIcon 的 Default / Dark / Tinted 外观符合平台要求。
- AppIcon 在 1024 / 180 / 60 / 40 / 29 px 和实际主屏裁切后仍可识别。

### 7.4 数据边界

- 开启飞行模式后完整签到、查看和删除。
- 模拟存储空间紧张时保存失败可恢复。
- 连续创建大量历史 fixture 后滚动和月份切换流畅。
- 删除 App 会丢失 P0 本地数据，此行为需与产品说明一致。

## 8. 回归测试触发条件

以下改动必须执行完整日期和统计回归：

- 修改 `LogicalDay`。
- 修改项目时区或日界线。
- 修改 `recordKey`。
- 修改 SwiftData schema。
- 加入补签、多项目或 CloudKit。
- 修改删除和恢复逻辑。

只修改视觉时，也至少执行首次启动、签到、重启恢复和删除四条核心路径。

## 9. 缺陷优先级

- `P0 阻断`：无法签到、记录丢失、重复记录、错误跨日、统计严重错误、清空错误目标。
- `P1 严重`：部分设备布局不可用、通知持续错误、删除失败无提示、VoiceOver 无法完成主流程。
- `P2 一般`：非阻断视觉、动画、文案或次要交互问题。

任何未关闭的 P0 缺陷都阻止工程 GO。
