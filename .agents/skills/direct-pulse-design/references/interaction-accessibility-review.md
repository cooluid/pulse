# Pulse UI/UX 与可访问性审阅

只在审阅信息架构、流程、控件、导航、错误、双语、Dynamic Type、VoiceOver 或隐私时读取。先确认领域事实与 1.0 范围，再审阅界面投影。

## 从用户任务出发

逐条写出用户的目标、起点、成功出口和失败恢复：

- 首次确认主承诺，并理解它可以稍后编辑。
- 看懂今天是否已签到，只执行一次签到，并确信事实已经保存。
- 查看最近七日、月历与统计，打开/删除一条明确记录。
- 修改主承诺、主题、语言、提醒、周起始日、触觉与签到时区。
- 导出、恢复或完整清除数据，并理解破坏性后果。

任何建议如果增加步骤、重复解释或引入新概念，必须证明它降低了错误或显著提高理解；“更完整”不是理由。

## 状态闭包

对每个受影响流程覆盖真实存在的状态：

- `loading / ready / saving / success / empty / disabled / error / confirmation`。
- 保存短于阈值时不闪加载器；超过阈值时只显示中性进度。
- 失败保留输入/当前页面和可重试入口，不提前关闭、不显示成功、不吞掉原始原因。
- 已签到、未来、项目开始前、漏签和今天待签到必须可区分，且不只依赖颜色。
- 禁用必须说明是当前不可操作，不要把“未选中”“低强调”和“不可用”画成同一种状态。
- 页面重建、回前台和重启从权威事实恢复，不重演刚完成才应出现的反馈。

## 导航与控件语义

- 主导航只有今日与记录两个根；各自保留 NavigationStack 状态。
- 设置是根页面之上的次级层；进入时主导航和不可见根内容都离开触控与辅助功能树。
- 使用 Button、Picker、Toggle、Form/List、Sheet 和 confirmationDialog 的正式语义；不以 `onTapGesture` 伪装按钮。
- 确认从真实触发控件呈现；删除、清除、导入替换等破坏性操作保持来源、目标与取消路径清晰。
- 月份可见按钮、滑动和辅助功能动作汇入同一状态变更入口，方向和动效一致。
- 所有点击目标至少 44 × 44 pt；视觉尺寸可以更小，但命中区和相邻控件不能冲突。

## 文案与低压力体验

- 用“今天还空着”“留下今天”“你随时可以回来”等中性语义，不制造断签恐惧、惩罚倒计时或竞争压力。
- 不用“写入本机后完成”等实现细节重复解释已经清楚的完成状态。
- 错误文案诚实说明没有保存、可以如何恢复；不要用温柔语气淡化数据风险。
- 主承诺和说明属于私密内容；通知和系统表面默认不复制正文。
- 中文界面使用“一日一印”，英文/其他语言使用“Pulse”，不在同一活动界面留下中英混排。

## Dynamic Type 与适配

- 从默认到 Accessibility 最大字号检查完整流程，而不是只检查单个控件。
- Accessibility 字号下签到圆改为可纵向扩展的通栏控件；底栏改为等宽入口并去掉副标题。
- 允许纵向滚动，但不能让固定底栏遮住最后一项；使用实际测量高度，不按设备硬编码补白。
- 4 / 12 字符边界名称、160 字说明、长时区名称、English 和本地化日期都必须参与测试。
- 检查键盘、焦点链和表单重排；“下一项/完成”应驱动明确焦点，不依赖点击坐标。

## VoiceOver 与非视觉等价

- 阅读顺序与视觉任务顺序一致：页面身份 → 当前状态 → 主动作 → 次级信息。
- 日期、签到状态、连续天数、日历状态、按钮行为和禁用原因具有清楚标签/值/提示/traits。
- 组合视觉元素时控制 accessibility element 边界，避免同一状态重复朗读或拆成无意义碎片。
- 不可见根页、装饰性脉冲场、重复品牌图形和纯视觉光环从辅助功能树移除。
- 已签到日使用真实 Button 打开详情；月份切换提供可发现的辅助功能动作。
- 用人工 VoiceOver 主流程作为 `HUMAN` 证据；标识符存在和 UI 测试通过不证明朗读体验自然。

## 系统辅助设置

- Reduce Motion：保留状态理解，去掉缩放、回弹、扩散和循环呼吸。
- 降低透明度：导航和表面仍有明确边界与对比。
- 增强对比度/灰阶：状态仍由形状、图标或文字成立。
- 深色模式：不出现待执行比完成更亮、阴影脏污、细线消失或系统 Form 未品牌化的问题。
- Voice Control/键盘场景涉及的标准控件应保持系统可发现性，不用自定义手势替代。

## UX 结论边界

自动 UI 测试可证明元素存在、几何关系和流程可执行；它不能单独证明文案理解、VoiceOver 节奏、触觉、误触率或长期无压力体验。缺少人工证据时，分别报告自动化工程结论与 UX/可访问性候选结论。
